# Lessons

- Saat menulis atau menyusun dokumentasi proyek (PRD, SDD, spesifikasi teknis, ADR), selalu gunakan bahasa Inggris sebagai bahasa kanonis dokumentasi sistem kecuali jika pengguna secara eksplisit meminta bahasa lain.
- Always adhere strictly to `DESIGN.md` light theme specifications (`surface: #FFFFFF` page canvas). Prohibit dark canvas backgrounds (`bg-slate-950`). Use Atlassian semantic lozenges with visible 1px borders, sentence case for all UI copy (buttons, table headers, labels, lozenges), and never substitute un-tokenized neon gradient palettes for canonical Atlassian design tokens.
- Dilarang keras mengada-ada atau menanam data mock/hardcoded (dummy data) di frontend hanya demi mencocokkan tampilan visual dengan referensi gambar tanpa integrasi data nyata. Jika sistem belum memiliki endpoint atau struktur data pendukung, jelaskan batasannya secara transparan kepada pengguna dan bangun endpoint backend yang murni menghitung data riil dari database/telemetri, atau tawarkan visualisasi alternatif yang sepenuhnya kompatibel dengan data sistem yang ada.
- Saat selesai mengimplementasikan fitur atau menyelesaikan tugas, dilarang langsung melakukan operasi `git commit` maupun `git push` secara otomatis tanpa persetujuan pengguna. Selalu lakukan verifikasi lokal terlebih dahulu (linting, tests, build), laporkan ringkasan perubahan yang telah selesai, dan minta izin eksplisit dari pengguna sebelum menjalankan `git commit` dan `git push`.
- For this MES RBAC design, treat an explicitly requested System Administrator as a documented GLOBAL full-access role across every catalog permission, including integration operations; retain auditing, session controls, and validation even for that role.
- For this MES target architecture, distinguish system ownership from integration access: MES is operated only by the Production department. Quality, Maintenance, Warehouse, and PPIC own and work in QMS, MMS, WMS, and PPSS respectively; MES exchanges integration data with those systems rather than assigning their departmental users MES roles.
- Dilarang keras membuka, membaca, atau menampilkan file rahasia atau file lingkungan (`.env`, private keys, password, access token) sesuai aturan ketat `SAFE-OPERATIONS.md`. Gunakan deklarasi skema atau variabel lingkungan yang didokumentasikan tanpa pernah mencetak isi file sensitif.
- Ketika pengguna merespons pertanyaan klarifikasi atau memilih opsi arsitektural (misal: "opsi b"), susun dan sampaikan rencana langkah kerja terukur (concise plan) terlebih dahulu sebelum langsung melakukan eksekusi masif terhadap kode dan database.
- Selalu patuhi panduan codestyle (`.agent-knowledge/static/rules/codestyle/TYPESCRIPT-NESTJS.md` dan `REACT.md`) serta jaga konsistensi bahasa Inggris pada seluruh dokumen proyek kanonis (`PRD.md`, `ARCHITECTURE.md`, `DATABASE.md`).
- In ISO 22400-2 & SEMI E10 OEE calculations, always dissociate calendar time (24h) from Planned Production Time (PPT). Non-scheduled time (off-shift periods, weekends, and factory shutdowns without scheduled orders) must be explicitly categorized as Non-Scheduled Time and excluded from PPT, preventing catastrophic degradation of Availability and false reporting of massive undefined hours.
- In multi-cavity injection molding Performance calculations, theoretical operating time must be computed as total shots multiplied by ideal cycle time per shot (or total parts multiplied by cycle time per cavity unit), never multiplying total parts directly by the full shot cycle time which multiplies cavity count twice.
